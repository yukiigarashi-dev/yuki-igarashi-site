## AI Prompts

> **使い方**: 記入済みの `tasks/task-XXX.md` をエージェントに読み込ませてから投げる。
> **順番**: Prompt A → B → C の順で使う。スキップしない。

---

### Prompt A｜着手前確認（必ずここから始める）

```
このtask.mdを読んで、実装を始める前に次をやれ。
1. Read firstのファイルを全部読め
2. Acceptance criteriaを読んで実装方針を箇条書きで出せ
3. 不明点・判断が必要な点があれば今聞け
判断が全部できたら「実装を開始します」と言え。
```

---

### Prompt B｜実装

```
このtask.mdに従って実装しろ。
- Constraintsを必ず守れ
- Acceptance criteriaを全部満たせ
- Out of scopeには手を出すな
- 完了したらVerificationのコマンドを実行して結果を見せろ
```

---

### Prompt C｜完了確認

```
このtask.mdを読んで、実装が完了しているか確認しろ。
1. Acceptance criteriaを1つずつ確認し Pass/Fail を出せ
2. Verificationを実行して結果を貼れ
3. Deliverablesが全部揃っているか確認しろ
4. Out of scopeに触れていないか確認しろ
全部PassならPRを出していい。Failがあれば修正しろ。
```

---

### Prompt D｜スタック時 → ハーネス改善ループ

```
このtask.mdと現在の状況を読んで、次をやれ。

【原因分析】
1. 何が問題かを1文で言え
2. 原因を分類しろ:
   - ドキュメント不足（何が書かれていれば詰まらなかったか）
   - ツール不足（何があれば解決できたか）
   - 制約の曖昧さ（何が明確なら判断できたか）
   - その他

【解決】
3. 解決策を3つ出せ（メリット・デメリット付き）
4. 推奨案を1つ選び理由を言え
コードはまだ書くな。方針が決まってから書く。

【ハーネス改善】
5. この詰まりを再発させないために、ハーネスの何を直すべきか言え
   - CLAUDE.md に追記すべきこと
   - テンプレートに追記すべきこと
   - docs/ に新たに作るべきドキュメント
6. 上記の改善をこのリポジトリに反映しろ（ドキュメントの更新・追記）
```

---

### Prompt E｜セッション再開時（作業を途中から再開するとき）

```
このtask.mdのStatusとDecision logを読んで、次をやれ。
1. 前回どこまで完了しているか要約しろ
2. 次にやるべきことを1つ特定しろ
3. Read firstのうちまだ読んでいないファイルがあれば読め
確認が終わったら「ここから再開します：（次のアクション）」と言え。
```
