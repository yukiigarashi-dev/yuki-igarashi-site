# Garbage Collection — ドキュメントの腐敗と制約違反を検出する

> **目的**: リポジトリを定期的にスキャンして、陳腐化したドキュメント・
> 実態と乖離した仕様・守られていない制約を検出・修正する。
>
> **頻度の目安**: 大きな機能追加のあと、または2週間に1回。
> エージェントに任せて回す。人間がレビューするのは差分だけでいい。

---

## Prompt A｜ドキュメント鮮度チェック

```
このリポジトリのdocs/を全部読んで、次をやれ。

【鮮度チェック】
以下の観点で各ドキュメントをスキャンしろ:
- src/の実装と矛盾している記述
- tasks/done/の完了タスクで変わったはずなのに更新されていない記述
- TBDや「要確認」のまま放置されている項目
- 存在しないファイル・関数・APIへの参照

【出力形式】
| ファイル | 問題の内容 | 深刻度（high/mid/low） | 推奨アクション |
|---|---|---|---|

深刻度highのものから修正PRを出せ。
修正は事実に合わせて書き直すだけ。推測で補完するな。
不明な場合は「要確認: （何が不明か）」と書いて残せ。
```

---

## Prompt B｜仕様と実装の乖離チェック

```
docs/specs/とsrc/を照合して、次をやれ。

1. specs/に書かれたAcceptance criteriaのうち、
   実装されていない・または実装が異なるものを列挙しろ
2. 実装されているがspecsに記載がない機能・挙動を列挙しろ
3. Non-goalsに書かれているのに実装されているものを列挙しろ

各項目について:
- 実装を直すべきか、仕様を更新すべきかを判断しろ
- 判断できない場合は「要確認」として残せ
- 修正が明確なものはそのまま修正しろ
```

---

## Prompt C｜tasks/の棚卸し

```
tasks/active/を読んで、次をやれ。

1. Statusが`done`になっているのにactive/に残っているタスクを
   tasks/done/に移動しろ
2. Statusが`not_started`のまま長期間放置されているタスクを列挙しろ
   （Decision logや更新日がないものも対象）
3. 重複・矛盾しているタスクがあれば指摘しろ

tasks/done/に移動したファイルはリストにして報告しろ。
```

---

## Prompt D｜アーキテクチャ制約チェック

```
docs/architecture.mdとsrc/を読んで、次をやれ。

1. architecture.mdに定義された依存関係ルールに違反しているimport・参照を検出しろ
2. 違反箇所をファイル名・行番号付きで列挙しろ
3. 各違反について修正方法を提案しろ

architecture.mdが存在しない場合は:
「architecture.mdが存在しません。
src/の構造からドメイン・レイヤー構成を推測してたたき台を作成します」
と言ってからdocs/architecture.mdのたたき台を生成しろ。
```

---

## Prompt E｜GC完了レポート

```
今回のガベージコレクションで行った変更をまとめて、
docs/quality.mdを更新しろ。

記載内容:
- 実施日
- スキャンしたファイル数
- 検出した問題数（深刻度別）
- 修正した件数
- 未解決の「要確認」項目一覧
- 次回GCまでに人間が判断すべきこと

quality.mdが存在しない場合は新規作成しろ。
```
